Privacy Policy

Whoop Loop

A single-user personal health application built on the WHOOP Developer API. This policy describes exactly what it reads, where that data is kept, and the only three places any of it is ever sent.

Effective 8 September 2026 Version 1.0 Users 1 (the developer)

01 What this application is

Whoop Loop is a personal, self-hosted application written by one developer for their own use. It runs on that developer's own computer, is operated through a private Telegram bot with a single authorized chat, and has no public interface, no sign-up, and no other users.

There is no company behind it, no commercial offering, and no plan to distribute it. If it is ever offered to anyone else, this policy will be rewritten before that happens.

02 Data accessed from WHOOP

With the account owner's explicit authorization, the application reads the following through the WHOOP Developer API, using these scopes:

  • read:recovery — recovery score, heart rate variability, resting heart rate, blood oxygen, skin temperature
  • read:cycles — daily strain and energy expenditure
  • read:sleep — sleep stages, duration, efficiency, respiratory rate, sleep need and debt
  • read:workout — workout type, duration, heart rate zones, energy expenditure
  • read:profile — first name, last name, email address on the WHOOP account
  • read:body_measurement — height, weight, maximum heart rate
  • offline — a refresh token, so the application can sync without re-authorizing every hour

The application only reads. It never writes to, modifies, or deletes anything in the WHOOP account.

03 Where the data lives

All WHOOP data is stored in a single SQLite database file on the developer's own machine. Alongside it the application stores data the developer enters directly: body weight, food and calorie entries, and short diary notes about alcohol, caffeine, stress, and how they felt.

There is no cloud database, no hosted backend, and no third party holding a copy of the health history. The OAuth tokens are stored in that same local file and are never transmitted anywhere except back to WHOOP to refresh a session.

04 What leaves the device

Three services necessarily receive data, because the features that use them run remotely. Nothing else is ever sent anywhere.

Data Goes to Why
WHOOP physiological history stays local Stored and analyzed on the device only
Weight, food, calorie entries stays local Stored and analyzed on the device only
Bot messages and summaries Telegram Telegram is the interface; messages pass through it in transit
Voice note audio OpenAI Speech-to-text transcription of spoken diary entries
Diary note text Anthropic Turning a free-form note into structured fields
Worth being clear about

Voice and diary features are optional. With no OpenAI key configured, voice transcription is disabled and voice notes are never uploaded. With no Anthropic key configured, notes are parsed locally with pattern matching and no note text leaves the device. Neither provider is sent WHOOP physiological data, and neither is sent anything that identifies the account holder.

05 What the application does not do

  • No data is sold, rented, licensed, or shared with any third party.
  • No advertising, no ad networks, no marketing profiles, no tracking pixels.
  • No analytics or telemetry of any kind is collected or transmitted.
  • No data from any other person is collected — the application has exactly one user.
  • No automated decisions with legal or similarly significant effects are made. Its output is informational only and is not medical advice, diagnosis, or treatment.

06 Retention and deletion

Data is kept for as long as the developer chooses to keep it, because the file sits on their own disk. There is no server-side copy to request the deletion of.

To remove everything: delete the local database file, which erases the full history and the stored tokens at once. To cut off future access independently, revoke the application from the WHOOP account's connected-apps settings; the refresh token stops working immediately.

07 Security

All traffic to WHOOP, Telegram, OpenAI, and Anthropic uses TLS. API credentials and tokens are held in a local environment file and a local database, neither of which is committed to version control. The application binds its OAuth callback server to the loopback interface, so it is not reachable from the network.

Because the application runs on a personal machine, the practical security of the data is the security of that machine.

08 Children

The application is not directed at children and is not used by anyone under 16. Its only user is the developer.

09 Changes to this policy

If what the application does with data changes, this page is updated and the effective date at the top changes with it. Since there is one user, there is no separate notification mechanism.
